# AI導入を運営モデル再設計として評価する

## 結論

このサンプルは、AI導入責任者が「誰がどの業務を作り替え、その成果をどの根拠で評価するか」を確認するための判断地図です。

Deutsche Telekom（DT）の公開情報を例に、顧客対応、ネットワーク運用、音声サービス、社内業務、B2Bの5業務レイヤーを比較します。

このサンプルで採用した公開情報だけで6項目をすべて説明できる業務レイヤーはありません。

したがって、サンプルの「判断可能な再設計プロセス率」は0/5、0%です。

この結果は、DTのAI導入が失敗していることを意味しません。

このサンプルで採用した公開情報だけでは、投資判断に必要な測定経路を再現できないことを意味します。

次の行動は、各業務責任者が指標定義と測定経路を補い、AI導入責任者が証拠を再評価することです。

## 診断の問い

利用率以外の業務成果について、責任者、指標定義、測定経路、情報源、AIへの帰属、独立検証を説明できますか。

1項目でも説明できない場合は、成果を断定せず、担当者を決めて測定設計へ戻します。

## このマップで判断できること

| 判断対象 | 確認する内容 | 不足した場合の行動 |
|---|---|---|
| 誰が作り替えるか | 業務成果に責任を持つ役割 | 業務責任者を割り当てる |
| 何を作り替えるか | 5業務レイヤーの対象プロセス | 評価対象を業務プロセス単位へ分解する |
| 何を成果とするか | 指標名、単位、対象期間、分母 | 指標定義を作る |
| どう測るか | データ源、取得方法、確認頻度 | 測定経路を設計する |
| 数値を誰が公表したか | 情報源とURL | 出典を確認する |
| AIの効果といえるか | AIへの帰属と留保 | AI単独の効果と断定しない |
| 第三者が確認したか | 独立検証の有無 | 会社自己申告値として扱う |

## 3分で見る順序

1. CJMで、AI導入責任者が対象選定から判断更新まで進む順序を確認します。
2. SBPで、経営、AI統括機構、現場、業務責任者、計測担当の分担を確認します。
3. Outcomeで、「判断可能な再設計プロセス率」の分子と分母を確認します。
4. EMで、5業務レイヤーの証拠分類と次の行動を確認します。

## 用語

AI Competence Center（AICC）は、DTが2023年に設立した、グループのAI専門性を集約して技術支援を提供する組織です。

first-call resolutionは、顧客の問い合わせを最初の連絡で解決できた割合です。

情報源は、数値を誰が公表したかを示します。

独立検証は、公表主体とは別の組織が数値や算出方法を確認したかを示します。

AIへの帰属は、観測した結果をAIによる変化として説明できる度合いです。

自律解決率は、AIが人間へ移管せずに解決した問い合わせの割合です。

このサンプルで参照する56%は、分母をall inquiriesと記載していますが、母集団の範囲は公表されていません。

## 4種類のDSLの役割

### CJM

CJMは、AI導入責任者の判断の流れを示します。

対象業務の選定、現場実験、業務再設計、成果計測、証拠評価、判断更新の6段階で構成します。

### SBP

SBPは、判断を支える責任配置を示します。

CJMミラーレーンは、CJMのアクションと同じIDを使います。

業務責任者レーンには、5業務レイヤーの再設計タスクを1件ずつ置きます。

矢印は、対象選定から判断更新までの主経路を左から右へ接続します。

5業務の詳細タスクは並行して扱うため、直列の矢印では接続しません。

各詳細タスクは、`source_id`でCJMの再設計アクションとの対応を保持し、主経路の再設計タスクの下へまとめます。

このサンプルのレーン名と分掌は、自組織へ差し替えるための役割名です。

責任割当と投資判断を含む分掌は、DTの正式な職務分掌を断定するものではありません。

### Outcome

Outcomeは、AI導入を判断できる状態を定義します。

KPIは「判断可能な再設計プロセス率」です。

分子は、6項目をすべて満たす評価対象プロセス数です。

分母は、評価対象に選んだプロセス数です。

目標値は100%です。

現在値はDSLに格納せず、この解説で管理します。

### EM

EMは、判断を成立させる行動と知識を示します。

工程横断の行動9件と、業務レイヤー別の再設計行動5件で構成します。

検証対象にした公開情報をナレッジとして登録します。

## 6項目の充足条件

| 項目 | 充足条件 |
|---|---|
| 責任者 | 業務を再設計する役割を特定している |
| 指標定義 | 指標名、単位、対象期間、分母を定義している |
| 測定経路 | データ源、取得方法、確認頻度を特定している |
| 情報源 | URL、発行主体、公開年を確認している |
| AIへの帰属 | 「AI運用を直接計測」または「因果帰属を分離できない」を根拠付きで記録している。「対象外」は未充足とする |
| 独立検証 | 「あり」または「なし」を根拠付きで記録している |

各業務レイヤーでは、採否にかかわらず主根拠を1件指定します。

主根拠は、AI運用を最も直接的に測る値を選びます。

該当する値がない場合は、公開情報で確認できる導入事実を選びます。

主根拠が存在しない場合は「未指定」と記録し、責任者以外の5項目を未充足とします。

6項目は、その主根拠の責任者とメタデータに対して判定します。

採否は成果を断定できるかの判定に使い、6項目の充足判定から主根拠を除外する条件には使いません。

## 証拠の分類

### 情報源

| 値 | 意味 |
|---|---|
| 会社一次資料 | DTが年次報告や会社スピーチで公表した情報 |
| 二次情報 | DT以外の組織がまとめた情報 |
| 出典未特定 | 参照先で数値や定義を確認できない情報 |
| 該当値なし | 評価する業務成果値も導入事実も指定されていない状態 |

### 独立検証

| 値 | 意味 |
|---|---|
| あり | 公表主体とは別の組織が数値や算出方法を確認している |
| なし | 会社自己申告値であり、独立した確認がない |
| 不明 | 独立した確認の有無を判断できない |
| 該当値なし | 評価する業務成果値も導入事実も指定されていない状態 |

二次情報が数値を再掲しているだけで、算出方法の確認を確認できない場合は「不明」とします。

### AIへの帰属

| 値 | 意味 |
|---|---|
| AI運用を直接計測 | AIが処理した件数やAIだけで解決した割合を測っている |
| 因果帰属を分離できない | 結果は確認できるが、AI単独による変化とは説明できない |
| 対象外 | 比較できる業務成果がなく、AIへの帰属を判定できない |

「AI運用を直接計測」は、AIが従来手段より成果を改善したという因果関係を意味しません。

## 根拠の採否

| 扱い | 条件 | 判断での使い方 |
|---|---|---|
| 中核根拠 | 出典と指標定義を確認でき、AIの運用を直接測っている | 主根拠として使う |
| 補助根拠 | 出典と指標定義を確認できるが、二次情報であるか、AIへの因果帰属を分離できない | 留保を付けて使う |
| 判断に使わない | 出典、指標定義、分母のいずれかを確認できない | 成果判断から外す |

「判断に使わない」の条件は、ほかの条件より優先します。

## 5業務レイヤーの判定

| 業務レイヤー | 再設計責任者 | 主根拠 | 未充足項目 | 判定 |
|---|---|---|---|---|
| 顧客対応 | 顧客対応責任者 | Frag Magenta自律解決率56% | 指標定義、測定経路 | 証拠不足 |
| ネットワーク運用 | ネットワーク運用責任者 | 1日最大1,500件のmicro-eventsを特定 | 指標定義、測定経路、独立検証 | 証拠不足 |
| 音声サービス | 音声サービス責任者 | 2025年度実績の説明にあるvoicebotの6月提供開始（年は明記なし） | 指標定義、測定経路、AIへの帰属 | 証拠不足 |
| 社内業務 | 各業務部門の責任者 | AskT導入 | 指標定義、測定経路、AIへの帰属 | 証拠不足 |
| B2B | B2B事業責任者 | 未指定 | 指標定義、測定経路、情報源、AIへの帰属、独立検証 | 証拠不足 |

顧客対応は、公開された成果値が最もそろっている業務レイヤーです。

ただし、自律解決率の分母、内部データの取得方法、確認頻度を公開情報から再現できません。

そのため、6項目をすべて満たすプロセスは0件です。

## 判断できる場合と保留する場合

### 判断できる場合

顧客対応責任者が、自律解決率の分母、対話ログの取得方法、集計頻度、除外条件を追加したとします。

この場合は、自律解決率56%を会社報告の運用指標として使えます。

独立検証がないため、第三者が確認したROIとは表現しません。

### 判断を保留する場合

責任者、分母、測定経路のいずれかがない場合は、投資拡大を保留します。

初期調査で参照したHelloDigital記事では、CSAT 25%向上を確認できません。

そのため、この値は判断根拠へ加えません。

保留時は、SBPの計測担当へ戻り、不足項目を補う担当者と期限を決めます。

## 自組織へ差し替える項目

1. 5業務レイヤーを、自組織がAIを導入する業務プロセスへ置き換えます。
2. 「業務責任者」を、成果責任を持つ役職名へ置き換えます。
3. 主根拠を1件指定し、指標名、単位、対象期間、分母を記録します。
4. データ源、取得方法、確認頻度を記録します。
5. 情報源、AIへの帰属、独立検証を分類します。
6. 6項目を満たさないプロセスへ、次の測定行動を割り当てます。

## 既存サンプルとの使い分け

`enterprise-ai-reach-value` は、AIの到達率と利用率を業務成果から分けるためのサンプルです。

同サンプルは、情報源ごとに指標定義が異なるため横比較を避けます。

今回のサンプルは、1社の公開値を3軸で格付けし、業務責任者と測定経路へ接続します。

`ai-dev-org-standardization` は、開発組織のgolden pathとguardrailを設計するためのサンプルです。

今回のサンプルは、開発手順やガードレールを扱いません。
