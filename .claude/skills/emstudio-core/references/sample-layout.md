# 公開サンプルのSBPレイアウト規約

この規約は、Enablement Map Studioで共有または説明に使う公開サンプルへ適用します。

個人作業用のDSLでは`position`と`size`を省略できますが、公開サンプルでは画面を開いた直後に業務の順序とCJMとの対応を判別できる配置を作ります。

## 主経路

- 順序のあるSBPタスクは、左から右へ配置します。
- 順序のあるSBPタスクは、`right`から`left`へ向かう矢印で接続します。
- 主経路のタスク間には、描画されたカードの境界を基準として200座標単位以上の間隔を設けます。
- 矢印がタスクや別の矢印と重なって順序を判別できない場合は、タスクの位置またはレーン幅を調整します。
- 必要な間隔を確保するために、レーンの幅を広げて構いません。

## CJMとの対応

- CJMアクションとSBPを接続する場合は、対応する代表SBPタスクを一つ定めます。
- CJMアクションと代表SBPタスクは、描画されたカードの中心を基準として横方向の中心を揃えます。
- カード幅はラベルによって変わるため、YAML上の`position.x`を同じ値にするだけでなく、描画後の中心位置を確認します。
- CJMアクションから代表SBPタスクへ、`bottom`から`top`へ向かう下向きの矢印を接続します。
- 通常のSBPタスクには、対応するCJMアクションのIDを`source_id`に設定します。
- CJMアクション同士が重ならないように配置します。

## 並行タスク

- 同時に進められるタスクを、順序があるように直列の矢印で接続しません。
- 並行タスクは、対応する代表SBPタスクの下方へ配置します。
- 並行タスクにも、対応するCJMアクションのIDを`source_id`に設定します。
- 並行タスク間の矢印は、実際に依存関係がある場合だけ追加します。

## 画面での検証

公開サンプルはYAMLの検証だけで完了にしません。

Enablement Map Studioでサンプルを開き、原則として1800×1100ピクセルの画面で次の項目を確認します。

中心差の許容値には、OSやフォントによるカード幅の違いを含めます。

1. CJMアクションが重なっていない。
2. CJMアクションと代表SBPタスクの中心差が20ピクセル以内に収まっている。
3. 主経路の矢印から、業務の順序を判別できる。
4. CJMから代表SBPタスクへの矢印から、両者の対応を判別できる。
5. 矢印がカードを横切っていない。
6. 並行タスクが主経路として誤読されない。
7. レーンまたはタスクが表示領域から意図せずはみ出していない。

条件を満たさない場合は、`position`、`size`、接続ハンドルまたはレーン幅を調整し、同じ画面条件で再確認します。
